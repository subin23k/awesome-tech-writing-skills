# Contributing to Awesome Technical Writing Skills

Thank you for taking the time to contribute! This list is focused on a specific
niche: LLM-native, agent-based, and machine-readable skills and prompt
resources for technical writing workflows. Please read these guidelines
before submitting a pull request.

---

## What Belongs Here

This list is intentionally scoped. Submissions must fall into one of these
categories:

- **Agent skill files**: Structured skill definitions that instruct an LLM agent how to perform technical writing tasks
  such as drafting, editing, tone enforcement, or style compliance.
- **Prompt libraries**: Collections of reusable prompts specifically designed
  for technical writing use cases: API documentation, release notes, changelogs,
  user guides, onboarding content, etc.
- **Linting configs**: Configuration files that enforce writing
  standards programmatically in a docs-as-code pipeline.

## What Does NOT Belong Here

To keep the list focused, please do not submit:

- General "awesome list of awesome lists" style community resources.
- Blog posts, courses, or video tutorials about technical writing.
- General-purpose writing tools or editors (Grammarly, Hemingway, etc.).
- Documentation platforms or static site generators (unless they expose
  machine-readable writing skill definitions).
- Resources unrelated to AI/LLM-assisted documentation workflows.

---

## Submission Guidelines

### Format

Each entry must follow this exact format:

```markdown
- [Resource Name](URL): One to two sentences explaining what the resource is
  and why it is relevant to LLM-assisted technical writing workflows.
```

- Use a colon (`:`) after the link, before the description.
- Keep descriptions factual and concise — no marketing language.
- Entries within a section are sorted **alphabetically by resource name**.

### Quality Standards

Before submitting, verify that your link:

- Points to a publicly accessible URL (no login required).
- Contains actual skill files, prompts, or rule configs — not just a landing page or README with no content.
- Is actively maintained or recently updated.
- Has not already been submitted or listed.

### Pull Request Process

1. Fork the repository.
2. Add your entry in the correct section, in alphabetical order.
3. Write a clear PR title: `Add [Resource Name]`
4. In the PR description, briefly explain why the resource fits the list's
   scope.
5. Submit the PR — a maintainer will review within 7 days.

---

## Suggesting a New Section

If your resource doesn't fit existing sections but clearly belongs in this
list, open an **Issue** first to propose the new section. Include:

- A proposed section name and one-line description.
- At least two resources that would go in that section.
- Why the section is distinct from existing ones.

---

## Code of Conduct

All contributors are expected to be respectful and constructive. Harassment,
spam, or self-promotion without genuine value to the list will result in
immediate rejection and blocking.
